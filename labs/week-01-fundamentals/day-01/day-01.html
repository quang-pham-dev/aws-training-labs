Part 01 · 00–10 min

Global Infrastructure

AWS uses geographically separated Regions, isolated Availability Zones, and distributed edge locations to support global workloads.

🌍 Region

Geographic area containing multiple AZs. Example: ap-southeast-1 (Singapore).

🏢 Availability Zone

One or more discrete data centers designed as an isolated failure domain.

⚡ Edge Location

Delivery point closer to users, often used by CloudFront caching.

Remember: An edge location is not another AZ. AZ names may map differently across AWS accounts.
Part 02 · 10–15 min

High Availability ≠ Disaster Recovery

HA reduces outages from failures. DR restores service after major incidents. RTO measures tolerated recovery time; RPO measures tolerated data loss in time.

Single-AZ

Simple, but AZ failure may take the entire API offline.

Multi-AZ

API tasks across AZs and a database failover strategy reduce AZ failure impact.

Backup & restore

Needed for deletion, corruption, and recovery. Multi-AZ alone is insufficient.

If an administrator deletes invoices, database replication may copy the deletion. Test backups and point-in-time recovery.
Part 03 · 15–20 min

Shared Responsibility

CUSTOMER · Security IN the cloud

Application code, IAM permissions, data, security configurations, dependency patching.

AWS · Security OF the cloud

Physical facilities, underlying hardware, core infrastructure and service-specific managed layers.

Service boundary matters: EC2 customers manage guest OS patching; managed services like Lambda shift more infrastructure work to AWS.
